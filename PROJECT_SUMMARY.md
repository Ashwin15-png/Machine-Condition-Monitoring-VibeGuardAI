   - **Manual Registration (`/readings/new`):** Input manual inspection readings to test backend DSP plausibility bounds and spike filtering.
   - **Reports (`/reports`):** Export full multi-format operational extractions in PDF, Excel, CSV, or JSON.

## 📊 Signal Processing (DSP) & Anomaly Pipeline

1. **Plausibility Bounds Validation:** Rejects out-of-range sensor noise (e.g. Temperature min -20°C / max 150°C, Vibration 0 - 100 mm/s).
2. **Spike Detection & Median Filtering:** Identifies transient non-physical spikes ($>5\sigma$ deviation) and applies a 5-sample median filter window to smooth real-time signals.
3. **Noise Reduction:** Applies Exponential Moving Average ($\alpha = 0.3$) to extract physical equipment baseline trends.
4. **ISO 10816 Vibration Severity Classification:**
   - **Class A / B (Good / Satisfactory):** Vibration $< 4.5\text{ mm/s}$
   - **Class C (Unacceptable / Warning):** Vibration $4.5 - 7.1\text{ mm/s}$
   - **Class D (Critical Damage):** Vibration $> 7.1\text{ mm/s}$
5. **Health Score Calculation:** 0 - 100% composite formula evaluating temperature baseline offsets, peak RMS vibration, and RPM deviation.

## 🗄️ Database Schemas & Data Models

- **`users`**: Platform administrators and operators with BCRYPT hashed credentials and role permissions.
- **`machines`**: Core asset registry detailing machine names, model numbers, locations, baseline limits, and current operating status.
- **`telemetries`**: Chronological high-frequency streaming log containing temperature, $X/Y/Z$ vibration, RMS vibration, RPM, voltage, current, pressure, and power.
- **`readings`**: Hardened, manually verified sensor inspection logs assigned unique sequential IDs (`RDG-1001`, `RDG-1002`).
- **`alerts`**: Active and acknowledged industrial warning/critical alarms triggered by threshold breaches.
- **`maintenance`**: Preventive and corrective maintenance schedules and work orders.
- **`predictions`**: Analyzed arrays containing Remaining Useful Life (RUL) limits and degradation slopes computed every 5 seconds.

## 🔐 Security & Engineering Standards

* **Stateless JWT Authorization:** Protected REST endpoints strictly validate cryptographically signed JWT bearer tokens.
* **Environment Variable Protection:** Zero hardcoded database URIs or JWT secrets; all credentials are managed exclusively via environment variables (`MONGO_URI`, `JWT_SECRET`).
* **Clean Code & DRY Principles:** Shared UI primitives (`Button`, `Input`, `Card`, `Badge`, `Modal`, `ConfirmDialog`) and central API abstractions ensure maintainability.
* **Lightweight Performance:** Optimized React re-renders for 50-tick real-time graphs and sub-second page transitions.
